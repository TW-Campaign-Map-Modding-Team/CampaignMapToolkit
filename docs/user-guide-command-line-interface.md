# Using CAIME from the Command Line (CLI)

## Overview

Most of what you do in the CAIME editor can also be done from a terminal, without opening the editor window. This is the **command-line interface (CLI)**. With it you can:

- **Process** a map — everything under the **Process** menu.
- **Validate** layers — everything under **Tools > Validate**.
- **Create** a new project, from scratch or from a template.
- **Paint** with the Brush, Eraser, Line and Flood Fill tools, and read hexes like the Color Picker.
- **Fill swatches from the database** — add every region, ground type, climate, attrition or area of interest the map is missing.
- **Import and export layers** as `.hex_layer` files or images.
- **Query** a map — its name, game, size, layers, swatches, and everything about a single hex.
- **Change settings** — the same preferences as **Settings > Preferences**.
- **Batch** many edits into one run.

The CLI is useful when you want to:

- **Batch-process** several maps from a script or build pipeline.
- **Re-export** a map quickly without clicking through menus.
- **Automate** repetitive edits, such as painting a list of hexes or importing layers generated by another tool.
- **Inspect** a map from a script, for example to check which region a hex belongs to.

When you launch CAIME with arguments, it runs the requested command in your console, prints its progress, and exits — **no editor window ever appears.** Launching CAIME with no arguments opens the normal graphical editor exactly as before.

> **The CLI reuses the editor's own code.** A map processed, painted or edited from the command line ends up exactly as if you had done the same thing in the editor: the same output files, the same swatches, the same painting rules.

## Before You Start

The CLI uses the same settings as the editor. Make sure the following are in place before you rely on it:

1. **The Assembly Kit path must be set for the game you are working on.**
   Processing needs it, and so does anything that reads the game's database (such as [`fill-swatches`](#filling-swatches-from-the-database)). Set it once in the editor under **Settings > Preferences**, or from the command line with [`config`](#changing-settings):
   ```
   CAIME.exe config set assembly-kit-path="D:\Steam\steamapps\common\Total War WARHAMMER III\assembly_kit" --game warhammer3
   ```
   See [Settings & Preferences](user-guide-settings-and-preferences.md) for what this path is.

2. **For `--map-data` and `--dynamic-resources`, the map must be saved in the required location.**
   Exactly as in the editor, these two processing tasks require your project to be saved as `map.hex` inside:
   ```
   {Assembly Kit path}\raw_data\EmpireDesignData\campaign_maps\{your map name}\map.hex
   ```
   and they require the Assembly Kit application (Tweak.AssemblyKit) to be **closed**. Everything else can work with a `.hex` file in any location.

3. **If RPFM is your database source,** every command that opens a map prepares the database tables through RPFM, just as opening a project in the editor does. The RPFM path and the game's vanilla pack must be set — see [Database Source](user-guide-settings-and-preferences.md#10-database-source-assembly-kit-or-rpfm).

> **Tip:** Close the editor before running commands that edit a map you have open in it, or that change settings. The editor does not notice changes made behind its back, and saving in the editor would overwrite them.

## The Basics

### Command Syntax

Every invocation starts with a **command**, followed by that command's **options**:

```
CAIME.exe <command> [options]
```

| Command | What it does |
|---|---|
| `process` | Runs processing tasks — the **Process** menu. |
| `validate` | Validates layers — **Tools > Validate**. |
| `create` | Creates a new project — **File > Create new map**. |
| `paint` | Paints hexes with a swatch — the **Brush** tool. |
| `erase` | Clears hexes on a layer — the **Eraser** tool. |
| `line` | Paints a straight line of hexes — the **Line** tool. |
| `fill` | Fills a connected area — the **Flood Fill** tool. |
| `pick` | Shows the swatch each layer holds at a hex — the **Color Picker** tool. |
| `fill-swatches` | Creates swatches for the database entries the map is missing. |
| `import-layer` | Imports `.hex_layer` files — **Tools > Import > Layer data**. |
| `export-layer` | Exports layers to images or `.hex_layer` files — **Tools > Export > Layer data**. |
| `query` | Prints information about a map and its hexes. |
| `config` | Shows or changes settings — **Settings > Preferences**. |
| `batch` | Runs a file full of editing commands on one map in a single go. |
| `help` | Prints help. |

Option names are not case-sensitive. Many options have a short form, such as `-m` for `--map`. Wrap any value that contains spaces in double quotes.

> **Tip:** Run CAIME from a terminal such as **PowerShell** or **Command Prompt**, from the folder where `CAIME.exe` lives (or use the full path to the executable). Because CAIME is a windowed application, the CLI attaches to your terminal so you can read its output; control returns to your prompt automatically when it finishes.

### Getting Help

```
CAIME.exe --help              # every command, plus the process tasks and validate layers
CAIME.exe help paint          # one command's options and examples
CAIME.exe paint --help        # the same thing
```

The command-specific help is the quickest reference: it lists every option the command accepts and shows a few examples.

### Pointing at a Map

Every command that works on a map takes `--map` (short form `-m`) followed by the project's `.hex` file:

```
CAIME.exe query --map "C:\maps\my_map\map.hex"
```

Before any work begins, CAIME checks that a path was given, that it ends in `.hex`, and that the file exists. If not, it stops with an error and does nothing.

The map is then loaded exactly as the editor loads it — including its database, if the Assembly Kit path is set for its game. If the database can't be loaded you will see a warning, but commands that don't need it (painting, querying, layer import and export) still work.

### Saving Your Edits

Commands that change a map — `paint`, `erase`, `line`, `fill`, `fill-swatches`, `import-layer` and `batch` — **save the map in place** when they finish, just like pressing **Save** in the editor.

To keep the original untouched, add `--output` (short form `-o`) with a new `.hex` path. The edited map is written there instead, and the folder is created if needed:

```
CAIME.exe paint -m map.hex --layer roads --hex 10,10 --output map_with_road.hex
```

If a command turns out to change nothing, the map is not rewritten and CAIME says so (with `--output`, the copy is still written). If a command fails part-way, nothing is saved.

### Hex Coordinates

A hex is written as **`x,y`** — two whole numbers separated by a comma, with no space, for example `120,45`.

These are the same **X** and **Y** numbers the editor's [status bar](user-guide-main-interface.md#8-the-status-bar) shows under your mouse, and the same coordinates validation messages print. `x` runs from `0` to the map width minus one, `y` from `0` to the map height minus one. Use `CAIME.exe query -m map.hex --size` if you need to know the map size.

Commands that take hexes accept them two ways, and you can combine them:

- **`--hex x,y`**, repeated as often as you like: `--hex 10,10 --hex 11,10 --hex 12,10`
- **`--hexes-file <file>`** — a text file of `x,y` pairs separated by spaces or new lines. Anything after a `#` on a line is a comment.

```
# hexes.txt - the coastline road
10,10 11,10 12,10
13,11
14,11   # the bridge approach
```

### Layer Names

Layers are named in lower case with hyphens between words:

| CLI name | Layer | Games |
|---|---|---|
| `ground-types` | Ground Types | all |
| `climates` | Climates | all |
| `attritions` | Attritions | all |
| `regions` | Regions | all |
| `region-borders` | Region Borders | all except Rome II |
| `restrictions` | Restrictions | all except Rome II |
| `areas-of-interest` | Areas of Interest | Warhammer III, Three Kingdoms |
| `beaches` | Beaches | all |
| `rivers` | Rivers | all |
| `bridges` | Bridges | all |
| `town-sprawl` | Town Sprawl | all |
| `town-slots` | Town Slots | all |
| `roads` | Roads | all |
| `trade-routes` | Trade Routes | Rome II, Attila, Thrones of Britannia, Three Kingdoms |
| `impassable` | Impassable | all |

Capitals, underscores and spaces are ignored when matching, so `Ground_Types` and `groundtypes` work too. A command refuses a layer the map's game doesn't have, and lists the layers it does. `CAIME.exe query -m map.hex --layers` shows them for a particular map.

### Choosing a Swatch

`paint`, `line` and `fill` need to know which swatch to paint with. Pass `--swatch` (short form `-s`) with either:

- the swatch's **name** — a region key such as `wh3_main_combi_region_altdorf`, a ground type such as `forest`, or a built-in name such as `Main slot` or `Restriction level 3`; or
- its **id** — the number `query --swatches` prints next to it.

```
CAIME.exe query -m map.hex --swatches --layer town-slots
```
```
town-slots swatches (12):
   0  Main slot
   1  Port slot
   2  Slot #2
   ...
```

Layers with only one swatch — **roads, rivers, bridges, beaches, town sprawl, region borders, trade routes and impassable** — don't need `--swatch` at all.

### Game Names

Where a game is asked for, use one of: `rome2`, `attila`, `thrones-of-britannia`, `warhammer`, `warhammer2`, `warhammer3`, `three-kingdoms`, `troy`, `pharaoh`, `pharaoh-dynasties`. As with layers, capitals, underscores and spaces are ignored.

## Processing a Map

```
CAIME.exe process --map <path-to-.hex> (--all | <task> [<task> ...])
```

The `process` command always needs two things: **which map** to process (`--map`) and **which tasks** to run.

- **`--all`** runs every task in a sensible order (Map Data → Dynamic Resources → Pathfinding → Borders → Trade Routes → Lookup).
- **One or more individual task flags** run just those tasks. When you list several, they always run in that same order regardless of the order you type them, so results are predictable.

`--all` cannot be combined with individual task flags, and a run with no tasks at all is rejected.

Each task corresponds exactly to one entry in the **Process** menu. See [Processing & Exporting Your Campaign Map](user-guide-processing-and-exporting.md) for what each one reads and produces.

| CLI flag | Process menu item | Output file |
|---|---|---|
| `--map-data` | Map Data | `map_data.esf` |
| `--dynamic-resources` | Dynamic resources | `dynamic_resources.esf` |
| `--pathfinding` | Pathfinding data | `pathfinding.bin` / `.ppd` |
| `--borders` | Borders data | `borders.pbd` |
| `--trade-routes` | Trade Routes | `trade_routes.ptd` |
| `--lookup` | Lookup and Minimap images | `lookup_*` / `minimap_*` images |

All outputs are written to the same place as the editor:
```
{Assembly Kit path}\working_data\campaign_maps\{your map name}\
```

> **Borders:** in the editor, **Process > Borders data** first opens a window where you choose which kinds of region border to export. The CLI has no such window, so it exports with that window's defaults for the map's game — the same choices you get by opening the window and clicking **Export** straight away.

## Validating a Map

```
CAIME.exe validate --map <path-to-.hex> (--all | <layer> [<layer> ...])
```

The `validate` command checks a map for layer-specific issues without writing any files. It takes `--map` and the same `--all` / individual-flag choice as `process`. Results are printed as each layer is checked; a layer that fails is reported as `FAILED` and the command exits with code `2`. The log output above it says what was wrong.

Each layer flag corresponds to one entry in **Tools > Validate**:

| CLI flag | Validate menu item |
|---|---|
| `--rivers` | Rivers |
| `--town-slots` | Town slots |
| `--roads` | Roads |
| `--bridges` | Bridges |
| `--beaches` | Beaches |
| `--regions` | Regions |
| `--attritions` | Attritions |
| `--climates` | Climates |
| `--ground-types` | Ground types |
| `--impassable` | Impassable |
| `--town-sprawl` | Town sprawl |

## Creating a New Project

```
CAIME.exe create --name <map-name> --game <game> [--width <n>] [--height <n>] [--output <folder>] [--force]
CAIME.exe create --name <map-name> --template <template> [--output <folder>] [--force]
CAIME.exe create --list-templates
```

`create` does what **File > Create new map** does: it makes a project folder containing a new `map.hex`.

| Option | Meaning |
|---|---|
| `--name`, `-n` | The campaign map name, which also names the project folder. Required. It is written the way the editor writes it: lower case, spaces become `_`, and punctuation is dropped. CAIME tells you if it had to change it. |
| `--game`, `-g` | The game the map is for. Required unless you use a template. See [Game Names](#game-names). |
| `--width` | Map width in hexes. Must be even. Default `1016`. |
| `--height` | Map height in hexes. Default `720`. |
| `--template`, `-t` | Start from one of the bundled templates instead of an empty map. The template decides the game and the map size, so `--game`, `--width` and `--height` can't be used with it. The copied map is renamed to `--name`. |
| `--output`, `-o` | The folder to create the project folder in. By default it goes in the same **Projects** folder the editor uses. |
| `--force` | If a project folder of the same name already exists, **delete it** and create the new one in its place. Without `--force`, an existing project is left alone and the command stops with an error. |
| `--list-templates` | List the available templates and stop. |

Maps larger than the recommended hex count (731,520) are allowed but produce a warning, just as in the editor.

```
CAIME.exe create --name my_map --game warhammer3 --width 800 --height 600
CAIME.exe create --name my_map --game rome2 --output "D:\mods\maps"
CAIME.exe create --list-templates
CAIME.exe create --name my_attila_mod --template main_attila_map
```

When it finishes, `create` prints the path of the new `map.hex`, ready to pass to `--map`. A brand-new map has no regions, ground types, climates or attritions yet — use [`fill-swatches`](#filling-swatches-from-the-database) to add them from the game's database.

## Painting

The painting commands are the toolbar's tools without the mouse. They follow the same rules as the editor:

- **Beaches** can only be painted on land next to the sea; other hexes are skipped.
- Painting **roads, rivers, trade routes, regions or region borders** rebuilds the affected edge masks when the map is saved, exactly as painting in the editor does.
- Every painting command saves the map when it finishes — see [Saving Your Edits](#saving-your-edits).

Each command tells you how many hexes it painted. See [The Painting Toolbar](user-guide-toolbar-painting-tools.md) and [Painting with Swatches](user-guide-painting-with-swatches.md) for what each tool does in the editor.

### paint — the Brush

```
CAIME.exe paint --map <path> --layer <layer> [--swatch <name-or-id>] --hex <x,y> [--hex <x,y> ...] [--brush-size <n>]
```

Stamps the brush once at every hex you give, in order.

| Option | Meaning |
|---|---|
| `--layer`, `-l` | The layer to paint on. Required. |
| `--swatch`, `-s` | The swatch to paint with, by name or id. See [Choosing a Swatch](#choosing-a-swatch). |
| `--hex`, `--hexes-file` | Where to paint. See [Hex Coordinates](#hex-coordinates). |
| `--brush-size`, `-b` | `1` paints just the hex, `2` adds the ring of six around it, `3` the next ring, and so on. Default `1`. The editor's slider stops at 10; the CLI accepts any size. |

```
CAIME.exe paint -m map.hex --layer regions --swatch my_region --hex 120,45 --hex 121,45
CAIME.exe paint -m map.hex --layer ground-types --swatch forest --hex 300,200 --brush-size 5
CAIME.exe paint -m map.hex --layer roads --hexes-file road_hexes.txt
```

### erase — the Eraser

```
CAIME.exe erase --map <path> --layer <layer> --hex <x,y> [--hex <x,y> ...] [--brush-size <n>]
```

Clears the layer at each hex, with the same brush shape as `paint`. Erasing removes a road, river, bridge, beach, sprawl, border or trade route; removes a town slot; makes an impassable hex passable; sets restrictions back to level 0; and leaves regions, ground types, climates, attritions and areas of interest unassigned.

```
CAIME.exe erase -m map.hex --layer rivers --hex 80,12 --hex 81,12
CAIME.exe erase -m map.hex --layer town-sprawl --hex 50,50 --brush-size 3
```

### line — the Line Tool

```
CAIME.exe line --map <path> --layer <layer> [--swatch <name-or-id>] --from <x,y> --to <x,y> [--to <x,y> ...]
```

Paints the straight hex line from `--from` to `--to`, both ends included. Give several `--to` options to draw a connected path: each segment starts where the previous one ended. Every segment must join two different hexes.

```
CAIME.exe line -m map.hex --layer roads --from 10,10 --to 40,25
CAIME.exe line -m map.hex --layer rivers --from 5,5 --to 20,8 --to 32,20 --to 35,40
```

### fill — Flood Fill

```
CAIME.exe fill --map <path> --layer <layer> [--swatch <name-or-id>] --hex <x,y> [--hex <x,y> ...] [--source-layer <layer>]
```

Starting from each hex you give, paints every connected hex that has the same value on the **source layer** — the CLI's version of the [Flood Fill Source dropdown](user-guide-toolbar-painting-tools.md#flood-fill-source-dropdown). The source layer is the layer you paint on unless you choose another with `--source-layer`. It can be any of: `ground-types`, `attritions`, `climates`, `regions`, `impassable`, `roads`, `trade-routes`, `restrictions`.

```
# give a whole region the same climate
CAIME.exe fill -m map.hex --layer climates --swatch climate_temperate --hex 200,150 --source-layer regions

# replace one connected patch of ground type with another
CAIME.exe fill -m map.hex --layer ground-types --swatch forest --hex 200,150
```

### pick — the Color Picker

```
CAIME.exe pick --map <path> --hex <x,y> [--hex <x,y> ...] [--layer <layer> ...]
```

Shows which swatch each layer holds at a hex — the id and name you would pass to `--swatch`. Without `--layer` it reports every layer the map has. `pick` never changes the map.

```
CAIME.exe pick -m map.hex --hex 20,15 --layer regions --layer roads --layer climates
```
```
Hex 20,15:
  regions   88  att_reg_italia_neapolis
  roads     -  (none)
  climates  6  ROME_Med
```

`-  (none)` means the hex holds nothing on that layer — no road, or no climate assigned.

## Filling Swatches from the Database

```
CAIME.exe fill-swatches --map <path> (--all | --layer <layer> [--layer <layer> ...]) [--key <key> ...] [--dry-run]
```

The swatches for regions, ground types, climates, attritions and areas of interest come from the map itself. A new map has none, and a map may be missing ones the game's database has gained since. `fill-swatches` **creates a swatch for every database entry the map is missing**, exactly as if you had added each one with the **New** button in the layer's Actions section (see [Creating a New Swatch](user-guide-painting-with-swatches.md#creating-a-new-swatch)). Swatches the map already has are left alone.

| Option | Meaning |
|---|---|
| `--all` | Fill every one of these layers the map's game has. |
| `--layer`, `-l` | Fill just this layer: `regions`, `ground-types`, `climates`, `attritions` or `areas-of-interest`. Repeatable. |
| `--key`, `-k` | Only create the swatch for this database key. Repeatable. |
| `--dry-run` | List what would be created without changing the map. |

What is read from the database:

- **Regions** — the regions listed for this campaign map (matched by the map's name), land and sea.
- **Ground types** — every ground type in the game, land and sea.
- **Climates** and **attritions** — every one in the game. (Only land and sea terrain attritions are used, as in the editor.)
- **Areas of interest** — Warhammer III and Three Kingdoms only, for this campaign map.

`fill-swatches` needs the game's database: the Assembly Kit path must be set for the map's game, or RPFM configured if that is your database source.

```
CAIME.exe fill-swatches -m map.hex --all --dry-run
CAIME.exe fill-swatches -m map.hex --all
CAIME.exe fill-swatches -m map.hex --layer ground-types --key forest --key sea_ocean
```

## Importing and Exporting Layers

A layer can be saved to a `.hex_layer` file and loaded back into this or another map of the same size — for example to copy the roads from one version of a map to another, or to edit a layer in an external tool. Thirteen layers can be exported and imported: `ground-types`, `rivers`, `climates`, `attritions`, `regions`, `region-borders`, `beaches`, `bridges`, `town-sprawl`, `town-slots`, `roads`, `trade-routes` and `impassable`.

### export-layer

```
CAIME.exe export-layer --map <path> --dir <folder> (--all | --layer <layer> [--layer <layer> ...]) [--format image|binary|both]
```

| Option | Meaning |
|---|---|
| `--dir`, `-d` | The folder to write the files to. Created if it doesn't exist. Required. |
| `--layer`, `-l` | A layer to export. Repeatable. |
| `--all` | Export every layer the map has that can be exported. |
| `--format`, `-f` | `image` writes a PNG per layer, `layer_<name>.png` (the default). `binary` writes a `layer_<name>.hex_layer` file per layer, for `import-layer`. `both` writes one of each. |

Exporting never changes the map. Existing files of the same name in the folder are overwritten.

```
CAIME.exe export-layer -m map.hex --dir exports --all
CAIME.exe export-layer -m map.hex --dir exports --layer regions --layer roads --format binary
```

### import-layer

```
CAIME.exe import-layer --map <path> --file <layer-file> [--file <layer-file> ...]
CAIME.exe import-layer --map <path> --file <layer-file> --as <layer>
CAIME.exe import-layer --map <path> --dir <folder>
```

| Option | Meaning |
|---|---|
| `--file`, `-f` | A `.hex_layer` file to import. The file records which layer it was exported from, so it is imported into that layer. Repeatable. |
| `--as` | Import a single `--file` into this layer instead. |
| `--dir`, `-d` | Import every `.hex_layer` file in the folder. |

Every file is checked before anything is imported: it must belong to a layer this map has, it must have been exported from a map of the **same size**, and no two files may target the same layer. If any check fails, nothing is imported.

```
CAIME.exe import-layer -m map.hex --file layer_regions.hex_layer
CAIME.exe import-layer -m map.hex --file layer_roads.hex_layer --file layer_rivers.hex_layer
CAIME.exe import-layer -m map.hex --dir "C:\exports\old_map" --output map_v2.hex
```

## Querying a Map

```
CAIME.exe query --map <path> [--info] [--name] [--game] [--size] [--layers] [--swatches [--layer <layer> ...]] [--hex <x,y> ...] [--json]
```

`query` prints information about a map without changing it. Combine as many of these as you like:

| Option | Prints |
|---|---|
| `--info` | Map name, game, size and file path. This is what you get when you ask for nothing else. |
| `--name` | The campaign map name. |
| `--game` | The game the map is for. |
| `--size` | The map size, as `<width>x<height>`. |
| `--layers` | The layers the map has — its swatch types — and how many swatches each holds. |
| `--swatches` | The id and name of every swatch, layer by layer. Sea regions and sea ground types are marked `(sea)`. Add `--layer` (repeatable) to list only some layers. |
| `--hex`, `--hexes-file` | Everything about a hex: its type, its region, ground type, climate, attrition, area of interest, restriction level and town slot (as numbers and names), every flag (sea, land, passable, beach, cliff, coast, bridge, river, road, trade route, town sprawl, border), and the road, river, region and trade route edge masks. |
| `--json` | Print the answer as JSON instead of text, for scripts. |

```
CAIME.exe query -m map.hex
CAIME.exe query -m map.hex --hex 20,15
CAIME.exe query -m map.hex --swatches --layer regions
```
```
Hex 20,15:
  index             620
  type              Land
  region            88  att_reg_italia_neapolis
  groundType        0  brownlands
  climate           6  ROME_Med
  attrition         -1
  ...
```

A value of `-1` means nothing is assigned on that layer.

**For scripts:** asking for just one of `--name`, `--game` or `--size` prints the bare value and nothing else. `query` writes its answer to standard output and its progress messages to standard error, so you can capture the answer cleanly:

```powershell
$name = CAIME.exe query -m map.hex --name
$hex  = CAIME.exe query -m map.hex --hex 20,15 --json | ConvertFrom-Json
$hex.hexes[0].regionName
```

## Changing Settings

```
CAIME.exe config list
CAIME.exe config get <key> [<key> ...] [--game <game>]
CAIME.exe config set <key>=<value> [<key>=<value> ...] [--game <game>]
```

`config` reads and changes the same settings as **Settings > Preferences**. Changes are saved straight away and the editor picks them up the next time it starts.

| Key | Setting | Values |
|---|---|---|
| `assembly-kit-path` | The game's Assembly Kit folder. Per game. | An existing folder |
| `vanilla-pack-path` | The vanilla `.pack` the RPFM database source reads. Per game. | An existing file |
| `database-source` | Where database tables come from. | `assembly-kit` or `rpfm` |
| `rpfm-path` | The RPFM installation folder. | A folder containing a working `rpfm_cli.exe` |
| `hex-spacing` | The gap drawn between hexes in the editor. | `0` to `0.2` |
| `log-to-file` | Also write the log to a file. | `true` or `false` |
| `auto-save` | Auto-save open projects. | `true` or `false` |
| `auto-backup` | Back up open projects periodically. | `true` or `false` |
| `backups-to-keep` | How many auto-backups to keep per project. | A whole number; `0` keeps them all |
| `map-data-post-process` | The **Map Data Config Auto-Patch** option. | `true` or `false` |

`true` and `false` can also be written `yes`/`no`, `on`/`off` or `1`/`0`.

- **`list`** shows every setting, with the per-game ones listed for each game. It is what you get from `config` on its own.
- **`get`** prints settings' values. With a single key it prints the bare value. A per-game key without `--game` lists every game.
- **`set`** changes one or more settings. Per-game keys need `--game`. All the values are checked first — folders and files must exist, the RPFM folder must contain a working RPFM — and if any is wrong, **nothing** is changed. An empty value (`key=`) clears a path. Switching `database-source` to `rpfm` needs `rpfm-path` set, either already or in the same command.

```
CAIME.exe config list
CAIME.exe config get assembly-kit-path --game warhammer3
CAIME.exe config set assembly-kit-path="D:\Steam\steamapps\common\Total War WARHAMMER III\assembly_kit" --game warhammer3
CAIME.exe config set auto-save=false auto-backup=false backups-to-keep=5
CAIME.exe config set rpfm-path="C:\RPFM" database-source=rpfm
```

See [Settings & Preferences](user-guide-settings-and-preferences.md) for what each setting does.

## Running Many Edits at Once (Batch)

```
CAIME.exe batch --map <path> --file <commands-file> [--output <path>]
```

Running dozens of separate commands means loading and saving the map dozens of times. A **batch** loads the map once, runs every command in a file against it, and saves once at the end.

The commands file has one command per line, written exactly as on the command line but **without** `CAIME.exe`, `--map` or `--output`. Blank lines and lines starting with `#` are skipped. Quote values that contain spaces. These commands can be used: `paint`, `erase`, `line`, `fill`, `pick`, `fill-swatches`, `import-layer`, `export-layer` and `query`.

```
# edits.txt
fill-swatches --all
fill --layer ground-types --swatch grassland --hex 0,0
paint --layer regions --swatch my_region --hex 10,10 --brush-size 4
line --layer roads --from 10,10 --to 60,32 --to 80,32
import-layer --file "C:\exports\rivers layer.hex_layer"
pick --hex 10,10 --layer regions
```

```
CAIME.exe batch -m map.hex --file edits.txt
CAIME.exe batch -m map.hex --file edits.txt --output map_edited.hex
```

- **Every line is checked before any runs.** A misspelt command or option, or a missing required option, anywhere in the file means nothing runs, and each bad line is reported with its line number. Things that can only be checked against the map — a swatch name, a hex outside the map — are checked when their line runs.
- **Lines run in order** on the same loaded map, so a later line sees an earlier line's changes — for example, painting with swatches `fill-swatches` just created.
- **If a line fails, the batch stops and the map is not saved.** Your map is either fully edited or left exactly as it was.
- File paths in the commands file are relative to the folder you run CAIME from, not to the commands file.

## Worked Examples

**Process everything for a map:**
```
CAIME.exe process --map "C:\maps\my_map\map.hex" --all
```

**Re-export just pathfinding and trade routes:**
```
CAIME.exe process -m "C:\maps\my_map\map.hex" --pathfinding --trade-routes
```

**Validate every layer that has a validator:**
```
CAIME.exe validate --map "C:\maps\my_map\map.hex" --all
```

**Start a new Warhammer III map and give it the game's ground types, climates and attritions:**
```
CAIME.exe create --name my_map --game warhammer3 --width 800 --height 600
CAIME.exe fill-swatches -m "{Projects folder}\my_map\map.hex" --layer ground-types --layer climates --layer attritions
```

**Fill the whole map with one ground type, then paint a forest:**
```
CAIME.exe fill -m map.hex --layer ground-types --swatch grassland --hex 0,0
CAIME.exe paint -m map.hex --layer ground-types --swatch forest --hex 120,80 --brush-size 6
```

**Copy the roads and rivers from one version of a map to another of the same size:**
```
CAIME.exe export-layer -m old\map.hex --dir layers --layer roads --layer rivers --format binary
CAIME.exe import-layer -m new\map.hex --dir layers
```

**Check which region a list of hexes belongs to (PowerShell):**
```powershell
$result = CAIME.exe query -m map.hex --hexes-file settlements.txt --json | ConvertFrom-Json
$result.hexes | ForEach-Object { "$($_.x),$($_.y) -> $($_.regionName)" }
```

**Process several maps in a row (PowerShell):**
```powershell
$maps = "C:\maps\map_a\map.hex", "C:\maps\map_b\map.hex"
foreach ($m in $maps) {
    CAIME.exe process --map $m --all
    if ($LASTEXITCODE -ne 0) { Write-Host "FAILED: $m"; break }
}
```

## Exit Codes

Every command sets a process exit code so scripts can detect success or failure:

| Code | Meaning |
|---|---|
| `0` | Success — everything requested was done. |
| `1` | Invalid arguments — the command was rejected and nothing was changed. This includes a layer, swatch or hex that doesn't exist in the map. |
| `2` | Processing failure — the map could not be loaded or saved, or a task failed. |

In PowerShell the code is available as `$LASTEXITCODE`; in Command Prompt as `%ERRORLEVEL%`.

## Troubleshooting

**"No assembly kit path is configured for *\<game\>*."**
Set the Assembly Kit path for that game, either in the editor under **Settings > Preferences** or with `CAIME.exe config set assembly-kit-path="<folder>" --game <game>`. See [Changing Settings](#changing-settings).

**"Map file not found" / "The map file must be a .hex file."**
Check the path after `--map`. It must point to an existing file ending in `.hex`. Wrap paths containing spaces in double quotes.

**"Unknown command" / "Unknown option."**
The CLI refuses to run anything it does not recognise, so a typo can't silently do the wrong thing. Run `CAIME.exe <command> --help` to see the exact spelling of every option.

**"*\<Game\>* maps have no *\<layer\>* layer."**
Not every game has every layer — see [Layer Names](#layer-names). The error lists the layers this map does have.

**"The *\<layer\>* layer has no swatch '*\<name\>*'."**
Swatch names must match exactly (capitals aside). List the layer's swatches with `CAIME.exe query -m map.hex --swatches --layer <layer>`, and use the name or the id shown. If the swatch exists in the game's database but not in the map, add it with [`fill-swatches`](#filling-swatches-from-the-database).

**"Hex *x,y* is outside the map."**
Coordinates start at `0`, so the last column is the width minus one. The message gives the valid range.

**"The *\<game\>* database isn't loaded" (from `fill-swatches`).**
The Assembly Kit path isn't set for the map's game, or the database tables couldn't be read from it. Look for a warning just after the map was loaded, and check the path with `CAIME.exe config get assembly-kit-path --game <game>`.

**"A project already exists at …" (from `create`).**
CAIME won't overwrite a project unless you ask. Choose another `--name` or `--output` folder, or add `--force` to delete the existing project folder and replace it.

**An imported layer file is "the wrong size".**
A `.hex_layer` file can only be imported into a map with the same width and height as the one it was exported from. If you used `--as`, also check you named the layer the file was exported for.

**`--map-data` or `--dynamic-resources` reports a failure.**
These two tasks have the same strict requirements as in the editor: the project must be saved as `map.hex` under `{Assembly Kit path}\raw_data\EmpireDesignData\campaign_maps\{your map name}\`, the project must have no unsaved changes, and the Assembly Kit application must be closed. See [Processing & Exporting](user-guide-processing-and-exporting.md) for details.

**My edits disappeared after I saved in the editor.**
The editor keeps its own copy of an open map. Close the map in the editor before editing it from the command line, or reload it afterwards with **File > Reload**.

**The editor window opened instead of running the CLI.**
The graphical editor only opens when CAIME is launched **with no arguments**. If a window appeared, the arguments did not reach the program — check that you typed a command (such as `process` or `--help`) after the executable name.
